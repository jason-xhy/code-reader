# Code Reader 纯键盘黑盒全功能测试方案

日期：2026-11-22。测试员：子代理 A。目标：验证从规范进入代码、建立理解的完整阅读工作流。

## 边界与证据

不阅读仓库源码、README、快捷键实现配置；功能发现仅来自窗口中的可见提示。应用交互仅发送键盘，不点击、不调用 DOM 或注入功能。允许截图及观察界面。测试文档写入独立目录。秘密不进入报告。

## 执行顺序

1. 记录入口、屏幕与初始窗口尺寸；从可见快捷键提示建立功能清单。
2. 验证帮助、导航、焦点、退出/取消、弹窗与页面切换。逐项检查提示和实际按键是否一致，输入控件是否冲突。
3. 以规范和代码阅读为主线测试项目/文件打开、目录导航、阅读、搜索、跳转、关联、标记/笔记等所有可发现功能；按实际界面发现补全矩阵。
4. 通过界面自主完成模型设置，验证保存、反馈、重新进入后的持久性；执行真实 LLM 问答，检查等待/错误/取消与上下文行为。
5. 键盘调整窗口大小或系统缩放（如可达），检查大/小布局、遮挡、滚动、长内容与弹窗可达性。
6. 对主要按键、搜索和 LLM 至少重复观测；记录按键发出至下一截图可见结果的端到端时间。该时间包含自动化/截图开销，不能冒充应用内部精确延迟；超过可感知阈值的现象重复确认。
7. 汇总测试矩阵、缺陷、证据与未覆盖项，形成 test-report-a.md 与 issues.md，交 B 修复。

## 判定

每项标记通过、失败、受阻或未发现。缺陷记录编号、严重度、前置条件、逐键复现、预期/实际、影响及证据。P1 为核心阅读/数据完整性阻断，P2 为功能或键盘可达性失败，P3 为布局/提示/体验问题。对模型后端不可用、缺少凭据或系统键盘能力受限明确归因，不假报通过。
